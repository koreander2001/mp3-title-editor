# MP3タイトル編集アプリケーション 基本設計

[要件定義書](requirements.md)に基づき、フォルダ直下のMP3のタイトルとアルバム名を一覧で編集し、ユーザーの一括適用操作でファイルに反映する。

## 1. 採用技術と選定理由

| 技術 | 選定理由 |
|---|---|
| Python | 開発言語の前提。編集状態や一括処理を通常のPythonで記述し、GUIと切り離して検証できる。 |
| uv | 実行時と開発時の依存関係を管理し、`uv.lock` で開発・テスト環境を再現できる。 |
| wxPython | `wx.grid.Grid` がセルの直接編集と読み取り専用列に対応し、今回の一覧編集に適している。 |
| MutagenのID3 API | タイトル（`TIT2`）とアルバム名（`TALB`）を個別に扱い、保存するID3バージョンを指定できる。 |
| Python標準の `logging` | 診断ログの出力レベルとローテーションを管理できる。 |
| pytest | GUIや実ファイルから独立した単体テストと、一時フォルダを使う結合テストを同じ環境で実行できる。 |

Windows 11を対象とし、1フォルダあたり最大100件程度を想定する。Windows固有の処理への依存は可能な限り抑える。処理時間の数値目標とWindows 11以外の対応は、今回の設計範囲から外す。

## 2. アーキテクチャ

画面層にはMVP（Model–View–Presenter）を採用する。Viewは表示と入力を担当し、Presenterは画面操作とアプリケーション処理をつなぐ。編集セッションと一括処理はアプリケーション層に置く。

タグ入出力はポートとアダプターで分離する。アプリケーション層が必要なタグ操作を `TagStore` として定義し、Mutagenを使う実装を起動時に渡す。代替Viewと代替TagStoreを使い、画面の判断とファイル単位の失敗を単体テストで再現できる構成にする。

ファイル処理はバックグラウンドで1件ずつ実行する。操作開始時点の対象と差分をワーカーに渡し、結果をGUIスレッドでセッションと画面に反映する。処理中は編集、重複実行、フォルダ切り替えを抑止し、終了要求は処理結果を反映した後に判定する。

## 4. 主要モジュールの責務

| モジュール | 責務 |
|---|---|
| `presentation/main_window.py` | wxPythonの画面を実装する。フォルダ選択、セル編集、確認ダイアログ、進捗、処理結果を扱う。ファイル名と状態は読み取り専用とし、タイトルとアルバム名を編集可能にする。 |
| `presentation/view.py` | Presenterが画面に求める表示、確認、操作状態の切り替えを定義する。 |
| `presentation/presenter.py` | 操作の受付、確認の要否、実行中の操作制御、完了後の表示を判断する。 |
| `presentation/worker.py` | ファイル処理をバックグラウンドで実行し、進捗と完了をGUIスレッドに通知する。 |
| `application/session.py` | ファイルごとのパス、編集値、比較用の基準値をメモリに保持する。項目ごとの差分と未適用の有無を判定する。 |
| `application/operations.py` | フォルダ直下のMP3の列挙、読み取り、一括適用、一括再取得を実行し、ファイル単位の結果を返す。 |
| `application/tag_store.py` | タグの読み取りと指定項目の更新・削除のインターフェースを定義する。 |
| `infrastructure/mutagen_tag_store.py` | Mutagenでタグを読み書きし、タグ形式と値の個数を確認する。入出力エラーをアプリケーション層で扱える形に変換する。 |
| `logging_config.py`、`__main__.py` | ログ出力を設定し、各構成要素を接続してアプリを起動する。 |

## 5. モジュール間の依存関係

- Viewの具体実装はwxPythonを使い、ユーザー操作をPresenterへ通知する。Presenterは `view.py` のインターフェースを通して表示や確認を求める。
- Presenterは編集セッションと一括処理を利用する。バックグラウンド実行とGUIスレッドへの通知は画面層のワーカーが担う。
- 一括処理はアプリケーション層の `TagStore` に依存する。Mutagenアダプターはその契約を実装し、Mutagenへの依存を受け持つ。
- `__main__.py` が具体実装を接続する。アプリケーション層とPresenterは、wxPythonのウィンドウやMutagenを使わずに動作を検証できる。

## 6. データの流れ

### 操作ごとの状態遷移

| 操作 | 処理 |
|---|---|
| フォルダ選択 | フォルダ直下の全MP3を読み取り候補とする。成功したファイルを一覧に追加し、読み取った値を編集値と基準値に設定する。タグや項目が未設定なら空欄で表示する。 |
| セル編集 | 編集値だけを更新する。基準値との差分があるファイルを未適用とする。編集値を基準値に戻すと、その項目の差分は解消する。 |
| 一括適用 | セルの編集を確定し、一覧全体から基準値と異なる項目だけを書き込む。空欄に変更した項目はタグから削除する。成功した項目の基準値を更新し、失敗したファイルの編集値と基準値は保持する。 |
| 一括再取得 | 確認を挟まず、一覧の各ファイルを読み直す。成功した行は編集値と基準値を上書きする。失敗した行は編集値と基準値を保持する。失敗したファイル名と理由は処理結果として表示する。 |
| フォルダ切り替え・終了 | セルの編集を確定し、セッションの状態から確認の要否を決める。未適用がある場合は、編集を破棄して続行するか、操作をキャンセルして編集に戻るかを確認する。判定のための再読み取りは行わない。 |

基準値には、最後に読み取りまたは適用に成功した値を使う。未適用は項目の差分だけで判定する。一括適用では、差分があるファイルだけを書き込む。

### ID3タグの取り扱い

- 既存のタグはID3v2.3とID3v2.4を対象とし、保存時は元のバージョンを維持する。タグが付いていない正常なMP3には、初回保存時にID3v2.4を作成する。
- ID3v2.3とID3v2.4以外のID3タグ形式は対応外とし、対応外のID3タグを含むファイルは読み取り失敗として扱う。ID3v1がID3v2.3またはID3v2.4と併存する場合も、ファイル全体を読み取り失敗として扱う。
- タイトルまたはアルバム名のどちらかが複数値の場合は、ファイル全体を読み取り失敗とする。判定にはタグから取得した値の個数を使う。区切り文字を含むひとつの文字列は単一値として扱う。
- 更新対象は差分のあるタイトルとアルバム名に限り、他のタグと音声データを保持する。アプリ利用中の外部変更の監視や競合判定は対象外とする。

## 7. エラー処理方針

- 初回読み取りに失敗したファイルは一覧に追加しない。他のファイルの処理を続け、完了後に失敗したファイル名と理由を表示する。複数値の場合は該当項目も示す。
- 一括適用または一括再取得で一部が失敗しても、処理できるファイルは続行する。失敗したファイルの編集値を保持し、完了後にファイル名と理由を表示する。
- フォルダを列挙できない場合は理由を通知し、切り替え前の一覧を保持する。
- 保存では、元ファイルと同じフォルダの作業コピーを更新・保存し、再読み取りする。再読み取りに成功し、変更した項目の値が適用予定の値と一致する場合に元ファイルを置き換える。削除した項目は未設定であることを確認する。再読み取りに失敗した場合や値が一致しない場合は、そのファイルの適用を失敗とし、元ファイルを保持する。保存成否はファイル単位で扱う。
- 予期しない例外で処理を継続できない場合は、確定済みの結果を反映してから中断を通知する。

## 8. ロギング方針

通常起動ではユーザー領域にローテーション付きログを出力する。開発時は標準エラー出力でも確認できるようにする。

| レベル | 記録内容 |
|---|---|
| `INFO` | 操作の種類、対象件数、成功・失敗件数、所要時間。 |
| `WARNING` | 想定内のファイル操作失敗と原因の分類。 |
| `ERROR` | 予期しない例外と診断に必要な情報。 |

タイトル、アルバム名、フルパスは原則ログに含めない。ユーザーが対象を特定するためのファイル名と理由は画面に表示する。ログの保存先の詳細、容量上限、保持世代数は実装時に決める。

## 9. テスト方針

| 種別 | 検証内容 |
|---|---|
| 単体 | 差分と未適用の判定、基準値への手入力での復帰、再取得に失敗した行の編集値と基準値の保持、差分の有無による未適用判定、一部失敗時の続行を検証する。代替Viewで確認・キャンセル・処理中の操作制御を検証する。 |
| 結合 | 一時フォルダのテスト用MP3で、直下のみの列挙、初回読み取り失敗時の除外、日本語タグ、空欄による削除、v2.3・v2.4の維持、タグなしからのv2.4作成、対応外形式と複数値の拒否、対象外タグと音声データの保持、作業コピーの再読み取り失敗や値の不一致を含む保存失敗時に元ファイルが保持されることを検証する。 |
| GUI・受け入れ | Windows 11で、日本語IME、Tab・Enter、操作前のセル編集確定、フォルダ切り替えと終了の確認・キャンセル、確認を挟まない再取得、エラー一覧、約100件での一連の操作と画面の応答性を確認する。 |

### 要件定義書との整合性

一覧編集、差分だけの一括適用、確認を挟まない一括再取得、切り替え・終了時の確認、部分失敗時の続行は、[機能要件と完成条件](requirements.md#4-機能要件)に対応する。

要件定義書と本書は、フォルダ直下の全MP3を読み取り候補とし、初回読み取りに成功したファイルだけを一覧に表示する。初回読み取りに失敗したファイルは、処理後にファイル名と理由を表示する。対応するID3形式、タグなしの初回保存形式、複数値タグの扱いは本書で定める。

使用するライブラリのバージョン、ワーカーの通知API、内部の型やメソッド名は実装時に決める。
