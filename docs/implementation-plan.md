# MP3タイトル編集アプリケーション 開発計画

[要件定義書](requirements.md)と[基本設計書](design.md)に沿って、開発基盤、読み取り、編集と再取得、適用、受け入れ確認の順に進める。各フェーズで、その時点の機能を起動して確認し、`uv run --locked pytest`、`uv run --locked ruff check .`、`uv run --locked ruff format --check .`、`uv run --locked mypy src` を再実行する。

## フェーズ1　開発基盤の初期化

- **目的** — 開発環境を再現可能にし、GUIの起動と自動チェックを実行できるようにする。
- **実装範囲** — uvによるプロジェクト初期化、基本設計書に沿ったディレクトリ構成、開発ツール、pytest、Ruff、mypyの設定、最小限のwxPython起動口。
- **主要な作業** — `uv python install 3.12` でCPythonを取得し、`uv python pin 3.12` で使用する系列を指定する。既存のGitリポジトリ内に `src` 構成のパッケージを初期化し、画面層、アプリケーション層、入出力層と、単体・結合・GUIテストのディレクトリを用意する。wxPythonとMutagenを実行時依存、pytest、Ruff、mypyを開発依存に追加する。pytestの探索先を `tests`、Ruffのターゲットを `py312` とし、lintと整形を設定する。mypyは `pyproject.toml` でPython 3.12向けに設定し、アプリケーションコードを型チェックする。依存関係を `uv.lock` に記録する。
- **完了条件** — ロック済み依存関係から環境を構築でき、空のwxPythonウィンドウを起動・終了できる。
- **テスト・検証方法** — `uv sync --locked` と `uv run --locked pytest` を実行し、スモークテストでインストール済みパッケージを読み込めることを確認する。`uv run --locked ruff check .`、`uv run --locked ruff format --check .`、`uv run --locked mypy src` を実行し、`uv run --locked python -m mp3_title_editor` で起動を確認する。
- **依存するフェーズ** — なし。

## フェーズ2　フォルダ選択とMP3の一覧表示

- **目的** — Windows 11のGUIからフォルダを選び、保存済みのタイトルとアルバム名を確認できるようにする。
- **実装範囲** — wxPythonのView、Presenter、バックグラウンドワーカー、読み取り用の `TagStore` とMutagenアダプター。
- **主要な作業** — フォルダ直下の全MP3を候補としてバックグラウンドで1件ずつ読み取り、結果をGUIスレッドへ返す。成功分は読み取り専用の一覧に追加し、失敗分は処理後にファイル名と理由を表示する。
- **完了条件** — 読み取り成功分が一覧に表示され、タグや項目が未設定なら空欄になる。個別の失敗後も後続を処理でき、フォルダの列挙に失敗した場合は切り替え前の一覧を保持する。
- **テスト・検証方法** — 一時フォルダと実MP3で、直下のみの列挙、ID3v2.3・v2.4、日本語、タグなし・項目未設定、対応外形式、破損、アクセス失敗を検証する。ID3v1とID3v2.3の併存、ID3v1とID3v2.4の併存の両方について、初回読み取りに失敗して一覧から除外され、処理後にファイル名と対応外形式である理由が表示されることを確認する。タイトルまたはアルバム名が複数値なら読み取り失敗とし、区切り文字を含む単一値は読み取れることを確認する。GUIでフォルダ選択とエラー表示を確認する。
- **依存するフェーズ** — フェーズ1。

## フェーズ3　一覧編集・一括再取得・離脱確認

- **目的** — アプリ内で編集し、保存済みの値への再取得や、未適用時の離脱確認を行えるようにする。
- **実装範囲** — タイトルとアルバム名のセル編集、編集セッション、未適用判定、一括再取得、フォルダ切り替え・終了時の確認。
- **主要な作業** — 編集値と、最後に読み取りまたは適用に成功した値を基準値としてセッションで管理する。未適用は編集値と基準値の差分だけで判定する。再取得に成功した行は編集値と基準値を上書きし、失敗した行は両方を保持する。失敗したファイル名と理由を処理結果として表示する。操作前にセル入力を確定し、離脱確認にはセッションの状態を使う。処理中は編集、重複実行、フォルダ切り替えを抑止し、終了要求は結果反映後に判定する。
- **完了条件** — 編集値を基準値に戻すとその項目の差分が解消される。再取得は確認を挟まず実行できる。再取得に失敗した行も、差分がある場合だけ未適用となる。未適用時の切り替え・終了では破棄かキャンセルを選べ、キャンセル後は編集を継続できる。
- **テスト・検証方法** — 代替Viewと代替 `TagStore` で、差分解消、再取得の成功・部分失敗、失敗した行の編集値と基準値の保持、失敗した行に差分がある場合とない場合の切り替え・終了確認、破棄・キャンセル、処理中の終了要求を検証する。GUIでセル確定を確認し、編集と再取得の前後でMP3の内容が変わらないことを確認する。
- **依存するフェーズ** — フェーズ2。

## フェーズ4　一括適用と安全な保存

- **目的** — 編集した項目だけをMP3に反映し、ファイル単位で失敗から再試行できるようにする。
- **実装範囲** — 差分の一括適用、空欄による値の削除、ID3バージョンの維持、作業コピー経由の保存、ファイル単位の結果反映。
- **主要な作業** — 差分のある項目だけを `TagStore` に渡す。同じフォルダの作業コピーを更新・保存する。再読み取りに成功し、変更項目の値が適用予定の値と一致することを確認してから元ファイルを置き換える。削除した項目は未設定であることを確認する。既存のID3v2.3・v2.4は元のバージョンで保存し、タグなしMP3には初回保存時にv2.4を作成する。成功した項目の基準値を更新し、失敗したファイルの編集値と基準値を保持する。
- **完了条件** — GUIから一括適用し、再取得で保存結果を確認できる。個別の失敗後も後続を処理し、完了後にファイル名と理由を表示する。作業コピーを再読み取りできない場合や変更項目の値が一致しない場合は、元ファイルを保持する。編集値を保持したまま再試行できる。予期しない例外で処理を継続できない場合は、確定済みの結果を反映してから中断を通知する。
- **テスト・検証方法** — 実MP3で、片方の項目だけの更新、空欄による削除、バージョン維持、タグなしからのv2.4作成、変更対象外のタグと音声データの保持を確認する。保存・置換の失敗に加え、作業コピーの再読み取り失敗と、再読み取りに成功しても変更項目の値が一致しない場合を再現する。各ケースで元ファイルの保持、後続処理、再試行を検証する。差分がない行には書き込まないことも確認する。先行ファイルの適用成功後に処理を継続できない例外を再現し、成功済みの結果がセッションと画面に反映された後に中断が通知されることを確認する。
- **依存するフェーズ** — フェーズ3。

## フェーズ5　ログ整備とWindows 11での受け入れ確認

- **目的** — 動作を診断できるようにし、要件定義書の完成条件をWindows 11で確認する。
- **実装範囲** — Python標準の `logging` によるログ出力、全機能の回帰確認、Windows 11での受け入れテスト。
- **主要な作業** — ユーザー領域にローテーション付きログを出力し、操作、対象件数、成功・失敗件数、所要時間、失敗原因の分類を記録する。タイトル、アルバム名、フルパスは原則としてログに含めない。開発時は標準エラー出力でも確認できるようにする。
- **完了条件** — ロック済み依存関係から環境を再現でき、自動チェックがすべて通り、Windows 11で完成条件を満たす。処理の対象件数がログに記録される。
- **テスト・検証方法** — ログの出力レベルと記録項目を確認し、処理の対象件数がログに記録されることを検証する。Windows 11で日本語IME、Tab・Enter、右上の×とAlt+F4、入力直後の一括適用、部分失敗の表示を確認する。約100件のフォルダで一覧表示、編集、適用、再取得を通し、処理中の画面の応答を確認する。
- **依存するフェーズ** — フェーズ4。

## 要件の網羅性

以下の対応により、全フェーズの完了条件と検証で、要件定義書の確定済みの制約・機能要件・完成条件を網羅する。

| 要件・完成条件 | 実装・検証フェーズ |
|---|---|
| フォルダ直下のみの読み取りと一覧表示、未設定項目の空欄表示 | 2、5 |
| アプリ内の一覧編集、適用前のファイル内容の保持、基準値に戻した場合の差分解消 | 3、5 |
| 差分のあるタイトルとアルバム名だけの一括適用、空欄による値の削除 | 4、5 |
| 確認やファイルへの書き込みを伴わない一括再取得 | 3、5 |
| 未適用時のフォルダ切り替え・終了確認、キャンセル時の編集保持、判定時の再読み取りなし | 3、5 |
| 部分失敗時の続行とファイル名・理由の表示、適用・再取得失敗時の編集値と基準値の保持、差分に基づく未適用判定 | 2〜5 |
| Pythonによるデスクトップアプリ、Windows固有処理への依存の抑制、Windows 11で約100件を操作可能 | 1〜5 |

フォルダ直下の全MP3を読み取り候補とし、一覧には読み取り成功分を載せる。対応ID3形式、タグなしMP3の初回保存、複数値の扱いは基本設計書に従う。サブフォルダとMP3以外の処理、他のタグの編集、選択行だけの適用・再取得、適用済みファイルの復元は対象外とする。処理時間の数値目標、Windows 11以外への対応、外部アプリとの競合は今回の完了判定に含めない。
